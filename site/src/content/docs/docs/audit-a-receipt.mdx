## Your newest local run

```sh
apmx audit
```

With no arguments and outside a pull request, `apmx audit` takes the newest
receipt under `./.apm/` and, when its sibling `outputs/` is present,
re-hashes it against the receipt.

## A receipt from CI

`run.yml` uploads the receipt of record as the `apmx-receipt` artifact.
Download it and audit it against the policy of the repository that receives
the delivery:

```sh
gh run download RUN_ID -R OWNER/REPO -n apmx-receipt -D apmx-receipt
apmx audit apmx-receipt --policy apm-policy.yml
```

A real receipt of record from the `apmx-demo-shop` CI run, audited against
the shop's policy:

Two things differ from the local default:

- An explicit receipt does **not** re-hash `outputs/`; the Outputs row only
  checks that the statements agree (`1 file bound`). Add `--outputs DIR` to
  re-hash.
- Identity looks the signature up by a delivered file's digest. It finds that
  file in `--outputs DIR` or the receipt's sibling `outputs/`. With neither,
  it prints `signature not checked: no delivered file to look it up by (--outputs)`.

## Check delivered files

```sh
apmx audit apmx-receipt --outputs apmx-receipt/outputs
```

Every file in `DIR` is re-hashed against the receipt's subjects. A match
prints `[+] Outputs  1/1 delivered files match receipt subjects (re-hashed)`.
A changed file fails:

```text title="A delivered file edited after the run (v0.7.1 and main)"
[x] Outputs       handoff.json differs from its receipt subject (SHA-256)
```

## Without network

```sh
apmx audit apmx-receipt --offline
```

`--offline` launches no APM and uses no network. Three things are reported
as not checked: dependencies (`[!] ... not audited (offline)`), signatures
(`[!] Identity  signature not checked (offline)`) and org policy
(`[!] Policy  org policy not checked (offline)`). Only a local `--policy` file
is read; anything else is a usage error:

```text title="apmx audit receipt.intoto.jsonl --offline --policy org (main, trimmed)"
Error: --offline can only read a local --policy file; org, owner/repo and URLs need the network.
```

`--offline` is not a pass for signatures: with `require_signed`, and always
in a pull request, the verdict is INCOMPLETE.

## See what it records

```sh
apmx audit --explain             # every topic
apmx audit --explain outputs     # one topic
```

`--explain` prints what the receipt records instead of auditing it: no
policy, no network, no APM. Topics: `factory`, `stages`, `checks`,
`dependencies`, `outputs`, `all`.

## Export the inventory

`--export abom` writes the receipt's CycloneDX 1.5 inventory (the agent bill
of materials) to stdout, or to a file with `-o`. It never overwrites a file:

```text title="apmx audit --export abom (v0.7.1)"
$ apmx audit --export abom -o abom-v071.cdx.json
[+] CycloneDX 1.5 inventory written to abom-v071.cdx.json

$ apmx audit --export abom -o abom-v071.cdx.json
Usage: apmx audit [OPTIONS] [RECEIPT]
Try 'apmx audit --help' for help.

Error: abom-v071.cdx.json exists; refusing to overwrite it.
```

## Machine-readable output

```sh
apmx audit --format json
apmx audit --format sarif
```

JSON has the keys `schema`, `receipt`, `selection`, `result`, `exitCode`,
`reason`, `assurance`, `signed`, `rows` and `facts`. The `schema` is
`apmx-audit/2`.
<Badge text="Since the next release" variant="note" size="small" /> v0.7.1
prints `apmx-audit/1`.

SARIF is version 2.1.0, with one result per failed or warning row. Every key
and rule is in the [`apmx audit` reference](/apmx/docs/reference/audit/#output-formats).

## Verify without APMX

`scripts/verify_evidence.py`, in an APMX source checkout, loads APMX's
receipt verifier by file path and runs the same structural checks without
importing the `apmx` package:

```text title="scripts/verify_evidence.py (real output)"
$ python <repo>/scripts/verify_evidence.py apmx-receipt --require-evidence
{"assurance": "Unsigned content binding and format compatibility, not authenticated attestation.", "capabilities": 0, "definitionSha256": "c011c35b5790bc327355f427b73b56192e37b9e096d95bbf5dd9e6117480d05b", "evidence": "complete", "outputs": 1, "statements": 3, "status": "passed"}
```

The stock GitHub CLI can verify the trusted signer's verification summary on
a delivered file. Download the attestations first, then verify against the
downloaded bundle:

```text title="gh attestation (gh 2.102.0, real output)"
$ gh attestation download handoff.json --repo danielmeppiel/apmx-demo-shop
Wrote attestations to file sha256:4bfe1f7daa11fc9590f14ecb1c9a04abd749b10dd1f421aa85a850aaa27c00c5.jsonl.
Any previous content has been overwritten

The trusted metadata is now available at sha256:4bfe1f7daa11fc9590f14ecb1c9a04abd749b10dd1f421aa85a850aaa27c00c5.jsonl

$ gh attestation verify handoff.json --repo danielmeppiel/apmx-demo-shop --bundle sha256:4bfe1f7daa11fc9590f14ecb1c9a04abd749b10dd1f421aa85a850aaa27c00c5.jsonl --signer-workflow danielmeppiel/apmx/.github/workflows/run.yml --predicate-type https://slsa.dev/verification_summary/v1
```

The second command exits 0. Verifying directly, without `--bundle`, fails
with `HTTP 422: Invalid Argument - predicate_type invalid predicate type
provided`: GitHub's attestation list API rejects that predicate-type filter.
